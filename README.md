# よかっ棚 (MediaLog)

本、漫画、アニメなどの評価とメモを保存する個人用Webアプリです。公開先: https://aqw126.github.io/yokattana/

## 使い方

1. 「記録を追加」から作品を登録します（評価は★3〜5）。タイトルを入れて「作品を検索」を押すと、候補から選ぶだけで、タイトル・ジャンル・タグ（作者・監督・開発元など）・表紙画像が入ります。本は Apple Books と国立国会図書館サーチ（Apple Books にない本の表紙は、題名と作者で Apple Books を探して入れる）、漫画・アニメは AniList、映画・ドラマ・ゲームは Wikidata から探します。映画・ドラマ・ゲームの表紙は入りません（下の TMDB の設定をすると、映画・ドラマはポスターつきで探せます）。
   メモと引用では、ネタバレの部分を選んで「選んだ部分をネタバレにする」を押すと、`||` で囲まれ、カードや共有ページで隠れます（例：`最後に||犯人は兄||だと分かる`）。ネタバレの部分を選んでもう一度押すと解除、ネタバレの部分にまたがって選ぶと1つにまとまります。
   一覧は、検索・ジャンル・タグ・評価（★4.5〜5.0／4.0〜4.4／3.5〜3.9／3.0〜3.4）で絞り込み、並べ替えられます。
2. 「ログイン」から Google アカウントでログインすると、端末をまたいで自動で同期されます。
3. 長期利用のため、定期的に「バックアップを書き出す」でJSONを保存してください。読み込みの前には、現在の記録が自動でバックアップされます。

使っている技術と、その役割（コードの場所つき）は、[docs/TECHNOLOGY.md](docs/TECHNOLOGY.md) にまとめています。

## 映画・ドラマのポスター（TMDB）

1. [TMDB](https://www.themoviedb.org/) に無料登録し、[API の設定](https://www.themoviedb.org/settings/api)で API キーを発行します（個人利用・Website）。
2. 表示された「API キー」（32文字の英数字）を、`tmdb-config.js` の `apiKey: ''` の `''` の中に貼って、プッシュします。
3. 映画・ドラマは TMDB で探すようになり（ポスターつき、監督・制作者もタグに）、ゲームは引き続き Wikidata で探します。ページ下部に、TMDB の規約で必要なクレジットが出ます。

キーはページのソースから見えます。読み取り専用のキーですが、悪用されたら同じ画面で作り直してください。空に戻せば、元の動き（Wikidata、ポスターなし）に戻ります。

## ファイル構成

- `index.html`: 画面構造（CSP、外部スクリプトの固定とSRI、アセットのバージョン印）
- `styles.css`: 色・レイアウト・スマートフォン向け表示
- `app.js`: 登録、検索、並べ替え、バックアップ、同期
- `store.js`: この端末の保存先（IndexedDB）。記録・表紙・設定を分けて持つ
- `supabase-config.js` / `supabase-schema.sql`: Supabase の接続先とテーブル・RLS
- `tmdb-config.js` / `tmdb-logo.svg`: TMDB の API キー（空なら使わない）と、クレジット用のロゴ
- `manifest.webmanifest` / `icon.svg`: ホーム画面への追加用
- `sw.js`: オフライン対応（ネットワーク優先で、つながらないときだけ保存済みの内容を使う）。`tools/bump-version.py` がバージョンを更新します
- `theme.js`: 表示テーマ（自動・ライト・ダーク）を、描画前に反映します。他のサイトの中（iframe）では中身を隠します
- `share.html` / `share.js`: 共有リンクの閲覧ページ（読み取り専用）
- `guide.html`: 使い方（機能の説明）
- `privacy.html`: プライバシーポリシー（情報の扱いだけ）
- `tests/`: ブラウザで動く自動テスト。`python tests/run.py` で、ヘッドレス Chrome を使って実行します（`tests/index.html` を、ローカルサーバー経由で開いても確認できます）。アクセシビリティの確認も含みますテストのページは、終わると結果を `run.py` に送り返します（IndexedDB の読み書きを実際の時間で待つため）。
- `.github/workflows/test.yml`: プッシュと PR のたびに、上のテストを自動で実行します
- `tools/bump-version.py`: `styles.css` / `app.js` などを変更したら実行して、キャッシュ回避用の `?v=` を更新します
- `.github/workflows/keepalive.yml`: Supabase 無料枠の自動停止を防ぐ、週1回のアクセス

## データの扱い

- 記録はブラウザ内の IndexedDB に保存され（表紙は画像のまま、記録とは別に保存）、ログイン中は Supabase にも同期されます（記録はデータベース、表紙は Storage の自分だけのフォルダ。表紙は表示するときに、手元にないものだけを取ってきます）。以前の版で localStorage に保存していた記録は、最初に開いたときに自動で移し、移す前のデータは30日間、控えとして残します。IndexedDB を使えないブラウザでは、以前の方式（localStorage、約5MB）で保存します。
- 「データの管理」に、この端末の使用量（記録・表紙の数と容量）が出ます。
- 削除した記録は「ごみ箱」に30日間残り、その後は中身を消した「削除済み」の印だけを90日間残して、他の端末へ削除を伝えます。
- 「データの管理」から、JSON/CSVの書き出し、JSON/CSVの読み込み、アカウントの削除ができます。アカウントの削除には、`supabase-schema.sql` の `delete_my_account` を Supabase で一度実行しておく必要があります。
- 同期に失敗した記録は「同期待ち」として保持し、オンライン復帰時や1分ごとに再送します。
- クラウドに保存できるのは、1人あたり5000件・合計100MB、1件300KBまでです（無料枠を守るため）。表紙画像は端末で150KB以内に縮小します。上限は `supabase-schema.sql` の「記録の上限と、更新日時の補正」の部分で決まり、Supabase で一度実行しておく必要があります。
- 表紙は Supabase Storage の `covers` に置きます（1枚300KB、1人200MBまで）。使うには、`supabase-schema.sql` の「表紙の置き場所（Storage）」の部分を、Supabase で一度実行してください。実行するまでは、以前と同じく表紙を記録に埋め込んで同期します。実行したあとにログインすると、以前の形の記録は自動で新しい形に移ります（更新日時は変わりません）。
- 端末の時計がずれて未来の日時で保存された記録は、端末とクラウドの両方で今の時刻に直します（新しい方が勝つ同期で、上書きできなくなるのを防ぐため）。
- ログアウトすると、この端末の記録は消えます（クラウドに残ります）。

## 共有リンク

- 「共有」から、今の絞り込み結果（ジャンル・タグ・検索）、または1件を、読み取り専用のリンクにできます（ログインが必要です）。「選んで共有」では、カードのチェックで作品を手動で選んで共有できます（絞り込みを変えても選択は残り、100件まで）。
- 共有は、その時点の内容のコピーです。表紙画像・メールアドレスは含まれません。
- 期限切れのリンクは、週1回（keepalive）と、新しいリンクを作るときに削除されます。使うには、`supabase-schema.sql` の「共有リンクの整理」の部分を、Supabase で一度実行してください。
- メモと引用は、「含めない（既定）」「ネタバレの部分を除いて含める」「すべて含める」から選びます。「除いて」では、ネタバレの部分が「（ネタバレのため省略）」になって送られます。「すべて」では、閲覧ページでネタバレの部分が隠れ、押すとその部分だけが表示されます。
- 有効期限（7日・30日・なし）を選べ、いつでも停止できます。
- 使うには、`supabase-schema.sql` の `shares` と `get_share` の部分を、Supabase で一度実行してください。
